## 攻击点列表

### Attack-R4-1: "纯统计贡献"在临床期刊CBM中构成自我削弱
- **严重级别**: P1
- **攻击位置**: §1定位、§4.2 C1、附录D.1第3项
- **攻击内容**: R4将核心贡献重新定位为"Brier reliability改善作为纯统计贡献"，明确声明"不依赖特定临床场景"。但CBM（Computers in Biology and Medicine）是临床应用期刊，其发表标准要求论文展示对临床实践或生物医学研究的意义。将核心贡献明确定位为"纯统计贡献"且"不依赖临床场景"，等于主动声明论文无临床相关性。
- **反方论证**:
  1. **CBM期刊定位**：CBM的Aims and Scope明确关注"计算机方法在生物学和医学中的应用"。纯统计贡献（不依赖临床场景）更适合统计期刊（如Statistical Methods in Medical Research）或机器学习期刊（如Pattern Recognition）
  2. **R4自我承认**：附录D.1第3项明确承认"CBM审稿人可能不接受'纯统计贡献'作为临床期刊的贡献"，但仅给出"有fallback期刊"的应对——这等于承认核心贡献可能不适合CBM
  3. **攻击转移而非消除**：R4用P0-1规避了M4（阈值化决策不常见），但引入了新问题——核心贡献从"在ECG实践中不常见"变成"与临床实践无关"。从CBM审稿人视角，后者可能更严重：不常见但存在的场景尚可论证，与临床无关则直接质疑论文是否适合CBM
  4. **CBM审稿人视角**："作者明确声明核心贡献是'纯统计贡献'，不依赖临床场景。那这篇论文为什么投CBM而不是统计期刊？如果核心贡献与临床无关，论文的临床价值是什么？"
- **建议修复**:
  1. 不将核心贡献定位为"纯统计贡献"，改为"跨语料库ECG部署中TS对校准可靠性的改善"——强调ECG应用场景，但不依赖特定临床决策方式
  2. 保留Brier reliability作为主指标，但不声明"不依赖临床场景"——而是声明"在ECG跨语料库部署场景中的校准可靠性改善"
  3. 在Discussion中讨论Brier reliability改善对ECG临床部署的潜在意义，不声称"纯统计贡献"

### Attack-R4-2: E1标注"confirmatory"在统计学意义上不准确
- **严重级别**: P1
- **攻击位置**: §3.2 E1（line 122）、附录B diff表（line 3247）
- **攻击内容**: R4将E1（在跨语料库ECG迁移中运行8种已发表校准方法）标注为"Confirmatory"。但confirmatory replication在统计学中有严格定义：预注册假设+独立数据收集+预先分析计划。E1不满足任何一条。
- **反方论证**:
  1. **Confirmatory的统计定义**：Confirmatory analysis要求（a）预注册假设，（b）独立数据收集，（c）预先分析计划。E1不满足任何条件——A1是post-hoc analysis plan，数据已在9/2-9/8收集，分析计划在9/5后制定
  2. **E1的实际性质**：E1是在新数据集（跨语料库ECG）上应用已发表方法（TS、Platt、Isotonic等）。这在方法论上属于"systematic evaluation"或"method application study"，不是"confirmatory replication"
  3. **Replication的类型**：Direct replication（相同条件重复）→ Conceptual replication（不同条件验证同一理论）→ Generalization replication（新场景应用）。E1最多是generalization replication，不是confirmatory replication
  4. **R4自我承认**：附录D.1第5项承认"CBM审稿人可能不接受'confirmatory复现验证'作为贡献"
  5. **虚假二分法**：R4将E1标注"confirmatory"以规避M6（所有假设exploratory），但这个标签不准确。更诚实的做法是承认所有分析都是exploratory，但实验设计（数据集选择、评估指标）是预先确定的
- **建议修复**:
  1. 不使用"confirmatory"标签，改为"systematic evaluation of published methods"——诚实描述E1的性质
  2. 或者区分"confirmatory design"（实验设计是预先确定的）和"confirmatory analysis"（假设检验是预先注册的）——E1的实验设计可视为confirmatory，但分析不是
  3. 在论文中明确说明：E1是systematic evaluation，不是confirmatory replication；所有假设检验都是exploratory

### Attack-R4-3: "理论先验"论证本身是post-hoc rationalization
- **严重级别**: P1
- **攻击位置**: §4.3 §Methods假设分层诚实声明（line 3721-3736）、附录A.2（line 4073-4079）
- **攻击内容**: R4声称Brier reliability作为主检验有"理论先验"（theoretical prior），因为"TS不改变argmax → Brier reliability是自然主指标"。R4进一步声称"这一理论动机独立于实验结果，在A1创建前就已认识到"。但该论证首次出现在R4提案中，在R1-R3中均未提及。
- **反方论证**:
  1. **时间线证据**：R1方案定位为"边界条件刻画"，R2方案定位为"风险评估工具+预注册分支触发"，R3方案定位为"阈值化决策价值"。三个版本均未提及"TS不改变argmax → Brier reliability是自然主指标"这一"理论先验"。该论证首次出现在R4中，是在R3反方攻击M9（假设分层cherry-picking）后才提出的
  2. **Post-hoc rationalization的典型模式**：先看到数据/攻击 → 再构造理论解释 → 声称解释是先验的。R4的"理论先验"论证符合这一模式：R3攻击假设分层是post-hoc → R4构造"理论先验" → 声称先验独立于数据
  3. **不可验证性**：R4声称"在A1创建前就已认识到"，但无法提供任何证据——没有预注册文件、没有会议记录、没有git commit记录支持这一声称
  4. **审稿人视角**："作者声称Brier reliability的选择基于理论先验，但这一论证首次出现在论文中。作者如何证明这不是post-hoc rationalization？是否有任何pre-A1的记录支持这一声称？"
- **建议修复**:
  1. 诚实承认"理论先验"论证是在R4中提出的，不声称"在A1创建前就已认识到"
  2. 或者提供证据（如git commit历史、早期讨论记录）支持"理论先验"的先验性
  3. 将论证改为"基于TS的数学性质，Brier reliability是合理的主指标选择"——不声称"先验"，只声称"合理"

- **攻击内容**: R4将C2主贡献定位为"跨方向稳定性分析"，但只有6个迁移方向（n=6）。n=6无法提供任何有意义的稳定性评估——无法可靠估计方差、无法进行稳定性检验、无法提供有意义的置信区间。
- **反方论证**:
  1. **n=6的统计局限**：6个数据点只能计算描述性统计（均值、标准差），但不能进行推断性统计。n=6的95% CI宽度约为±1.96×s/√6 ≈ ±0.8s，如此宽的CI无法支持"稳定"的结论
  2. **"稳定性分析"的语义膨胀**：稳定性分析（stability analysis）在统计学中通常要求足够样本量来估计参数的变异度和分布。n=6的"稳定性分析"只是描述性统计，不是真正的稳定性分析
  3. **1.9× OOD/ID比率是单一汇总统计量**：从6个方向汇总出的1.9×比率是一个标量，不是"分析"。称其为"跨方向稳定性分析"是语义膨胀
  4. **审稿人视角**："作者声称进行了'跨方向稳定性分析'，但只有6个数据点。这不是稳定性分析，是6个数据点的描述性统计。你能从6个点得出什么稳定性结论？"
  5. **与M2的关系**：P1-4修补将C2从"诚实披露证伪"转向"跨方向稳定性分析"以规避M2（诚实披露不是贡献）。但如果"稳定性分析"只是n=6的描述性统计，那C2的贡献仍然不够——只是换了包装
- **建议修复**:
  1. 不使用"稳定性分析"一词，改为"跨方向描述性比较"——诚实反映n=6的局限
  2. 或者增加方向数（如使用leave-one-corpus-out生成更多迁移对），使n足够大
  3. 或者将C2贡献定位为"跨方向变异度的诚实报告"而非"稳定性分析"

### Attack-R4-7: EBT-LT"只需要未标注数据"未完全解决循环依赖
- **严重级别**: P2
- **攻击位置**: §4.2 C4 EBT-LT规格表（line 3603-3617）
- **攻击内容**: R4的P1-5修补明确EBT-LT只需要"少量未标注目标域数据"，不需要标注数据。这缓解了循环依赖的最严重形式（不需要标注数据），但未完全解决——未标注数据仍需目标域数据，且6个数据点的查表工具泛化能力存疑。
- **反方论证**:
  1. **未标注数据仍是目标域数据**：EBT-LT输入需要"源/目标先验距离"和"logit分布距离估计"。计算这些需要：(a) 目标域的未标注数据（用于估计先验分布）；(b) 在目标域数据上运行模型获取logits。用户仍需已有目标域数据
  2. **价值主张仍不清晰**：如果用户已有未标注目标域数据，为什么不直接用unsupervised calibration方法（如Confident Learning、CPSC）？EBT-LT基于6个数据点提供"经验性参考建议"，其价值不如直接在目标域上做无监督校准
  3. **6个数据点的泛化能力**：EBT-LT基于6个迁移方向的60个实验。6个方向的经验基础无法泛化到新的迁移对——新用户的数据集可能与这6个方向完全不同
  4. **部分缓解而非完全解决**：P1-5修补将循环依赖从"需要标注数据"降为"需要未标注数据"，这是部分缓解。但"部署前查表"的价值主张仍不清晰——用户需要已有目标域数据才能"部署前查表"
- **建议修复**:
  1. 诚实承认EBT-LT需要未标注目标域数据，不声称"部署前"（改为"部署准备期"）
  2. 或者明确EBT-LT只需要源域特征（如源域ECE、源域accuracy），不需要任何目标域数据——但这会进一步削弱工具的预测能力
  3. 诚实声明6个方向的泛化局限，不声称EBT-LT适用于新的迁移对

  1. 在Discussion中诚实讨论0.01量级Brier reliability改善的实际意义

  3. 或者将核心贡献从"效应量大小"转向"系统性评估的方法论贡献"——60实验+8方法+3语料库的系统性评估本身有价值，不依赖效应量大小

### Attack-R4-11: "TS不影响Brier score的resolution分量"的技术论证有误
- **严重级别**: P1
- **攻击位置**: §3.2 E3 TS数学性质声明（line 194）、§4.3 §Methods Properties of TS（line 3625-3643）
- **攻击内容**: R4声称"TS directly affects the reliability component without affecting the resolution component (which depends on argmax)"。但这一技术论证有误——TS改变概率分布，影响Brier score分解中的reliability和resolution两个分量。
- **反方论证**:
  1. **Brier score分解（Murphy 1973）**：BS = REL - RES + UNC，其中：
     - REL（Reliability）：校准度量，预测概率与观测频率的匹配程度
     - RES（Resolution）：区分度量，不同概率bin中观测频率的差异程度
     - UNC（Uncertainty）：基线不确定度
  2. **TS对RES的影响**：RES = Σ_b (n_b/N) × (x̄_b - x̄)²，其中x̄_b是bin b中的观测频率。TS改变预测概率 → 样本可能在不同bin间移动 → n_b和x̄_b改变 → RES改变
  3. **R4的错误**：R4声称"resolution component depends on argmax"，但resolution不依赖argmax——resolution依赖的是预测概率的binning和每个bin中的观测频率。TS不改变argmax，但改变概率值，从而改变binning和resolution
  4. **正确论证**：TS不改变argmax → top-1 accuracy不变。但TS改变概率值 → 影响所有概率依赖的指标（ECE、Brier score、Brier reliability、Brier resolution）。因此"Brier reliability是自然主指标"的论证不成立——TS影响Brier score的所有分量
  5. **对P0-1和P1-8的影响**：P0-1（核心贡献重新定位）和P1-8（理论先验声明）都依赖这一技术论证。如果论证有误，则"Brier reliability是自然主指标"的理论基础不成立
  6. **审稿人视角**："作者声称TS不影响Brier score的resolution分量，但TS改变概率分布，必然改变binning和resolution。这一技术论证有误。如果理论基础有误，核心贡献的定位是否成立？"
- **建议修复**:
  1. 修正技术论证：TS不改变argmax → top-1 accuracy不变 → 评估TS效果应使用概率依赖指标（如Brier score、ECE），而非决策依赖指标（如accuracy、F1）。不声称"TS不影响resolution"
  2. 或者使用更精确的论证：在rank-based binning下，TS不改变样本排序 → binning不变 → resolution不变。但需明确使用rank-based binning
  3. 不将"Brier reliability是自然主指标"作为"理论先验"，改为"Brier reliability是评估校准的合理指标之一"

### Attack-R4-12: NCV仍依赖阈值τ选择——τ=0.5在4类分类中任意
- **严重级别**: P2
- **攻击位置**: §4.3 §Methods NCV定义（line 3687-3716）、§4.3 §6.X（line 3744）
- **攻击内容**: R4的P1-7修补将NCV扩展为对称完整定义，但NCV仍依赖阈值τ。R4在§6.X中提到"τ=0.5主报告"，但τ=0.5在4类分类中是任意选择——4类分类中每类的自然阈值应为1/K=0.25。
- **反方论证**:
  1. **τ=0.5在4类分类中的问题**：在4类分类中，softmax输出满足Σp_k=1。如果τ=0.5，则最多有一个类p_k>0.5（因为如果两个类都>0.5，总和>1）。这意味着τ=0.5时，NCV只考虑"是否有一个类超过0.5"的决策——这退化为argmax决策（p_max>0.5 vs p_max≤0.5）
  2. **τ=0.25更合理但未被使用**：4类分类中，每类的自然阈值是1/K=0.25。使用τ=0.25会考虑更多决策变化，但R4使用τ=0.5
  3. **阈值敏感性未报告**：R4在§6.X提到"per-threshold DCR (τ=0.7/0.9)"作为exploratory，但未包括τ=0.25。如果τ=0.25的NCV与τ=0.5的NCV差异很大，则NCV的结论依赖阈值选择
  4. **M4/M5攻击的残留**：M4攻击阈值化决策不常见，M5攻击单一阈值任意。R4的P1-7修补解决了NCV定义不对称，但未解决阈值选择任意性
- **建议修复**:
  1. 报告多个阈值的NCV（τ=0.25, 0.5, 0.7, 0.9），展示阈值敏感性
  2. 或者使用数据驱动的阈值选择（如Youden J最优），并诚实声明in-sample拟合风险
  3. 在Discussion中讨论阈值选择对NCV的影响

### Attack-R4-13: Brier reliability vs ECE vs log loss——主指标选择不唯一
- **严重级别**: P2
- **攻击位置**: §3.2 E3 TS数学性质声明（line 194）、§4.3 §Methods（line 3625-3643）
- **攻击内容**: R4声称"Brier reliability是评估TS效果的自然主指标"，但TS不改变argmax的性质不唯一选择Brier reliability——ECE和log loss也不依赖argmax，同样是评估校准的合理指标。
- **反方论证**:
  1. **不依赖argmax的指标有很多**：ECE、Brier score、Brier reliability、log loss/NLL、sharpness——这些指标都不依赖argmax，都受TS影响。TS不改变argmax的性质不唯一选择Brier reliability
  2. **Brier reliability vs ECE**：ECE是校准文献中更常用的指标（Guo et al. 2017, Kull et al. 2019）。R4选择Brier reliability而非ECE作为主指标，需要额外论证——为什么Brier reliability比ECE更适合评估TS效果？

  4. **审稿人视角**："作者选择Brier reliability作为主指标，但ECE也是合理的校准指标，且在文献中更常用。为什么选择Brier reliability而不是ECE？选择是否受结果影响？"
- **建议修复**:
  1. 同时报告ECE和Brier reliability作为主指标，不单独选择Brier reliability
  2. 或者提供理论论证说明Brier reliability比ECE更适合评估TS效果（如Brier score是proper scoring rule，ECE不是）
  3. 在Methods中讨论指标选择的理由和局限性
