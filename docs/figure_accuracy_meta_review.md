## 逐点裁决分析

### Attack-1: 汇总图掩盖1/6方向TS恶化

**反方主张**：汇总图ΔECE=+0.077掩盖了cpsc→chapman方向ΔECE=-0.022的恶化；绿色编码对恶化方向虚假暗示改善。

**独立验证**：
```
cpsc→chapman, resnet1d, seed42:
  ECE_raw = 0.090842
  ECE_cal = 0.112415
  ΔECE = -0.021573（TS恶化）✓ 反方数值正确

汇总图6方向加权平均ΔECE = +0.076852 ✓
```

**裁决分析**：

1. **反例成立**：cpsc→chapman方向确实存在TS恶化（ΔECE=-0.022），数值验证通过。

2. **但"掩盖"是平均的固有属性**：汇总图标题明确标注"6-direction averaged reliability curve"（代码line 489-491）。任何多方向平均都会平滑个体差异——这不是缺陷，而是平均的定义。反方将"平均的固有平滑效应"等同于"故意掩盖"，属于**过度归因**。

3. **绿色编码误导成立**：正方§6.2声称"绿色暗示已校准/改善，符合直觉"，但对cpsc→chapman方向，TS后ECE从0.091增至0.112，绿色确实虚假暗示改善。这是**真实的信息误导**。

4. **缓解措施存在但不充分**：60补充图覆盖全方向，但主图和汇总图未标注恶化方向。读者需手动对比60张PDF才能发现1/6方向恶化。

5. **严重级别评估**：1/6=16.7%方向恶化，恶化幅度极小（|ΔECE|=0.022 vs 平均0.077），且汇总图已明确标注为"averaged"。Fatal过高，**降级为Serious**。

**裁决：PARTIAL（部分成立）**
- 成立部分：绿色编码对恶化方向误导；主图未标注恶化方向
- 不成立部分：汇总图"掩盖"是平均的固有属性，非缺陷
- 降级理由：恶化幅度小、比例低、汇总图已标注为平均

### Attack-2: 加权平均ECE与全局ECE差异54.56%

**反方主张**：TS后加权平均ECE=0.151 vs 全局ECE=0.098，差异54.56%，TS效果被低估39%。

**独立验证**：
```
加权平均 ECE_raw = 0.227516 ✓
加权平均 ECE_cal = 0.150664 ✓
加权平均 ΔECE   = +0.076852 ✓

"全局ECE"（padding K=4→K=5后pool所有样本）:
  global ECE_raw = 0.222756 ≈ 反方声称的0.222820 ✓
  global ECE_cal = 0.097477  ≈ 反方声称的0.097535 ✓
  global ΔECE   = +0.125280 ≈ 反方声称的+0.125285 ✓
```

**裁决分析**：

1. **反方数值正确**：我通过padding K=4数组到K=5（补零列）后pool所有样本，复现了反方的"全局ECE"。数值差异在浮点精度内一致。

2. **但"全局ECE"计算本身有语义问题**：6方向中2个K=5、4个K=4。Pool不同类数空间的样本计算ECE，相当于把不同尺度的confidence分布混合——这正是Attack-4指出的问题。反方用Attack-4指出混合K空间不成立，又在Attack-2用混合K空间的"全局ECE"作为基准，**逻辑自相矛盾**。

3. **图例标注充分**：代码line 466明确标注"Before TS (sample-count weighted mean ECE=...)"，line 489-491标题标注"6-direction averaged...ECE: sample-count weighted mean"。读者可从图例直接得知这是加权平均ECE而非全局ECE。

4. **正方未披露差异量级**：§5.4仅披露"加权平均ECE ≠ 全局ECE"的**存在性**，未披露54.56%的**量级**。已知局限表L5将影响评为"低"，对54.56%的差异确实低估。

5. **严重级别评估**：差异真实且大，但图例标注正确、汇总图是描述性可视化、且"全局ECE"基准本身有争议。Fatal过高，**降级为Serious**。

**裁决：PARTIAL（部分成立）**
- 成立部分：54.56%差异真实；正方未披露差异量级；L5影响评级过低
- 不成立部分：图例已标注"weighted mean ECE"；"全局ECE"基准有语义问题
- 降级理由：图例标注充分、描述性可视化、反方逻辑与Attack-4矛盾

### Attack-3: E6 ECE与CSV在cpsc→chapman方向差异-78.9%

**反方主张**：E6 ECE=0.091 vs CSV raw_ece_mean=0.415，差异-78.9%，"量级合理"主张不成立。

**独立验证**：
```
E6 cpsc→chapman resnet1d seed42: ECE = 0.090842 ✓
CSV cpsc→chapman seed42 noise0:  raw_ece_mean = 0.415340 ✓
差异 = (0.091 - 0.415) / 0.415 = -78.1% ✓

关键发现：CSV的ts_delta_ece_mean = -0.1267
          E6的ΔECE = -0.0216
          两者差异5.8倍 → 说明CSV与E6使用不同数据或不同ECE定义
```

**裁决分析**：

1. **反方数值正确**：E6 ECE=0.091、CSV=0.415、差异-78.9%均验证通过。

2. **但直接对比可能无效**：CSV的ΔECE=-0.127与E6的ΔECE=-0.022相差5.8倍。如果两者使用相同数据和相同ECE定义，ΔECE应该相近（即使ECE绝对值不同，TS带来的变化量应更可比）。5.8倍的ΔECE差异强烈暗示**CSV与E6使用不同的数据管线或不同的ECE定义**。

3. **正方"量级合理"论证确实以偏概全**：§2.3论证#3用ptbxl→chapman的0.108（与CSV的0.084相近）代表所有方向，声称"落在CSV范围[0.074, 0.907]内，量级合理"。但cpsc→chapman的0.091 vs CSV的0.415差异-78.9%，"落在范围内"是极弱的标准（任何0.074-0.907的值都满足），不能证明"量级合理"。

4. **CSV的ECE定义未确认**：正方§2.3自己标注"需确认（可能smooth_ece）"。如果CSV使用smooth_ece，则10-bin ECE与smooth_ece的对比本身就不完全有效。但smooth_ece与10-bin ECE通常差异5-15%，不足以解释0.091 vs 0.415的4.6倍差异。

5. **严重级别评估**：正方"量级合理"论证有缺陷（以偏概全），但反方-78.9%的对比可能无效（数据管线不同）。Serious合理。

**裁决：PARTIAL（部分成立）**
- 成立部分：正方"量级合理"论证以偏概全；"落在范围内"标准过弱
- 不成立部分：-78.9%直接对比可能无效（ΔECE差异5.8倍说明数据管线不同）
- 维持级别：正方论证缺陷真实，但反方反例的效力也有疑问

### Attack-4: 汇总图混合5类/4类空间

**反方主张**：汇总图对6方向ECE做加权平均，但6方向涉及不同类数空间（K=5和K=4），加权平均语义不成立。

**独立验证**：
```
方向              probs.shape    K(实际)  反方声称K  ECE_raw
ptbxl→chapman     (4050, 5)      5        5          0.107704
ptbxl→cpsc        (2057, 4)      4        4          0.373406
chapman→ptbxl     (2172, 5)      5        5          0.246077
chapman→cpsc      (2057, 4)      4        4          0.364260
cpsc→ptbxl        (2120, 4)      4        5(错误!)   0.418316
cpsc→chapman      (3958, 4)      4        5(错误!)   0.090842

实际：2个K=5方向，4个K=4方向
反方声称：4个K=5方向，2个K=4方向（2处事实错误）
```

**裁决分析**：

1. **反方表格有事实错误**：cpsc→ptbxl和cpsc→chapman的probs.shape实际为(2120, 4)和(3958, 4)，反方声称为(2120, 5)和(3958, 5)。2/6方向的数据错误。

2. **核心关切部分成立**：汇总图确实混合K=5和K=4空间的ECE。Top-label confidence的分布取决于K（K越大，max(prob)的期望越低），混合不同K的ECE在语义上有问题。

3. **但"系统性偏高"被反驳**：反方声称"4类目标(cpsc)的ECE系统性偏高"。实际数据：
   - K=4方向ECE：0.373, 0.364, 0.418, **0.091**（cpsc→chapman最低！）
   - K=5方向ECE：0.108, 0.246
   - K=4方向的ECE范围[0.091, 0.418]完全覆盖K=5方向[0.108, 0.246]
   - "系统性偏高"不成立——K=4方向既有最高ECE(0.418)也有最低ECE(0.091)

4. **严重级别评估**：核心关切（混合K空间）有一定道理，但反方证据有2处事实错误且"系统性偏高"被数据反驳。Serious过高，**降级为Minor**。

**裁决：PARTIAL（部分成立）**
- 成立部分：混合K=5/K=4空间的语义问题
- 不成立部分：反方表格2处事实错误；"系统性偏高"被cpsc→chapman(ECE=0.091)反驳
- 降级理由：证据质量差、核心论点被数据反驳

### Attack-7: bootstrap CI对极小样本bin退化为零宽区间

**反方主张**：ptbxl→chapman的bin 2有5个样本全部正确(accuracy=1.0)，bootstrap CI=[1.0,1.0]零宽退化。

**独立验证**：
```
ptbxl→chapman resnet1d seed42 bin 2:
  count = 5 ✓
  accuracy = 0.8000 (4/5正确) ← 反方声称1.0，实际0.8！
  correctness values = [0, 1, 1, 1, 1]
  bootstrap CI = [0.3333, 1.0000], width = 0.6667 ← 非零宽！

反方声称: accuracy=1.0, CI=[1.0,1.0] (零宽)
实际验证: accuracy=0.8, CI=[0.333,1.0] (宽度0.667)
```

**裁决分析**：

1. **反方核心证据有事实错误**：bin 2的5个样本中4个正确、1个错误，accuracy=0.8而非1.0。bootstrap CI=[0.333, 1.0]，宽度0.667，**完全不是零宽区间**。

2. **反例不成立**：反方构造的"5个样本全部正确→CI=[1.0,1.0]"的场景在ptbxl→chapman bin 2中**不存在**。反方可能未实际验证bin 2的correctness值，或验证了其他文件/方向但标注错误。

3. **理论关切有一定道理**：如果某bin确实有5个样本全部正确，bootstrap CI确实会退化为[1.0,1.0]。但这是一个**理论边界情况**，反方未能找到实际存在的实例。

4. **正方§3.4的阈值论证**：`len(col) >= 10`检查的是bootstrap后的有效值数量（1000），不是原始bin样本数。这一设计确实无法拦截原始样本极少的bin。但既然反方未能找到实际退化的实例，这一理论缺陷的实际影响为零。

**裁决：OVERRULED（驳回）**
- 驳回理由：反例不成立——bin 2实际accuracy=0.8非1.0，CI宽度0.667非零
- 反方核心证据有事实错误，可能未实际验证correctness值
- 理论关切存在但无实际实例支撑

### Attack-9: before/after CI共用同一rng

**反方主张**：ci_before和ci_after共用同一rng，bootstrap不独立，可能使Δaccuracy的CI偏窄。

**独立验证**：
```
代码line 700: rng = np.random.default_rng(args.rng_seed)
  → 单一rng创建 ✓
代码line 727-728: _compute_bins_and_ci(..., rng)
  → 同一rng传入，内部顺序调用 ✓
  → ci_before和ci_after的bootstrap重采样索引不独立 ✓
```

### "诚实披露"哲学争论的裁决

反方认为"披露不等于问题不存在——特别是当披露本身具有误导性时"。

**裁决**：反方观点**部分成立**。

1. **披露存在性确实不等于问题不存在**：正方披露"加权平均ECE ≠ 全局ECE"但不披露54.56%的量级，读者无法从披露中判断问题的严重程度。披露的**充分性**取决于是否包含了让读者做出正确判断所需的**关键信息**（如量级、方向、后果）。

2. **但披露确实提供了部分保护**：正方的披露使读者知道"差异存在"，可以主动查询细节。完全无披露 vs 有披露但不够详细，后者仍优于前者。

3. **披露具误导性的情况**：Attack-5/8中，§6.7在cherry-picking风险讨论中声称"淡色背景曲线展示变异性"，但实际展示的是方向变异性而非种子变异性。这种在特定上下文中**暗示错误信息**的披露，确实比不披露更糟——因为它给了读者虚假的安心感。

**结论**：正方的"诚实披露"策略需要从**存在性披露**升级为**充分性披露**——不仅披露问题存在，还要披露问题的量级、方向和后果。

### 汇总图角色定位的裁决

反方认为汇总图的多个问题使其"统计推断"角色下不可接受；正方认为汇总图是"描述性可视化辅助"。

**裁决**：汇总图定位为**描述性可视化辅助**，但正方需加强标注。

1. **代码证据支持描述性定位**：标题标注"6-direction averaged"、图例标注"sample-count weighted mean ECE"、CI用percentile非BCa、§3.5明确声明"视觉辅助"。

2. **但描述性可视化仍需无误导**：即使是描述性可视化，也不能：
   - 用绿色暗示改善而实际恶化（Attack-1/10）
   - 暗示种子变异性而实际只展示方向变异性（Attack-5/8）
   - 标注"ECE"而不区分"10-bin ECE"（Attack-6）

3. **结论**：汇总图作为描述性可视化可接受加权平均ECE≠全局ECE的差异（Attack-2降级理由），但仍需修补误导性标注。
