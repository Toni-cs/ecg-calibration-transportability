## 新发现攻击

### [严重] 攻击M1："证伪"叙事的语义陷阱——事后假设不能被"证伪"

- **攻击点**：R3 的 C2 叙事核心是"诚实披露证伪"，声明"We hypothesized that ID boundary condition satisfaction rate > 80%. The result (38.3%) falsified this hypothesis."但"证伪"（falsification）在科学哲学中暗示先验假设，而R3自己承认假设是事后提出的
- **攻击逻辑**：
  1. **"证伪"的科学哲学含义**：Karl Popper 的证伪主义要求先提出假设，然后用数据检验。证伪的逻辑结构是：先验假设 H → 数据 D → D 与 H 矛盾 → H 被证伪
  2. **R3 的实际情况**：R3 在 §2.1 承认"A1 修订案是事后分析计划（9/5 创建，部分实验已完成）"。A1.4.2 的分支触发条件（ID边界>80%）是在看到部分实验结果（9/2-9/4）后设计的
  3. **语义陷阱**：如果假设是事后提出的（看到38.3%后提出>80%），那"证伪"这个词就不准确——更准确的说法是"事后假设不被完整数据支持"或"事后合理化失败"。用"证伪"暗示了先验假设的科学严谨性，但实际是事后假设
  4. **审稿人视角**："作者说'falsified this hypothesis'，但假设是在看到部分数据后提出的。这不是falsification，是post-hoc hypothesis not supported by full data。用'falsification'一词是否过度包装了事后分析？"

- **证据**：
  - R3 §4.2 C2 诚实披露声明："We hypothesized that ID boundary condition satisfaction rate > 80%. The result (38.3%) falsified this hypothesis."
  - R3 §2.1："A1 修订案是事后分析计划（9/5 创建，部分实验已完成），不是预注册"
  - R3 附录A："A1 修订案（2026-09-05 创建）是基于部分实验结果（9/2-9/4 完成）的事后协议修订"

- **影响评估**：-3-5%（审稿人可能质疑"证伪"一词的过度包装，C2贡献进一步削弱）
- **建议修补**：将"falsified this hypothesis"改为"our post-hoc hypothesis was not supported by the complete data"或"the observed rate (38.3%) did not meet our hypothesized threshold (80%)"，避免使用"falsified"一词

---

### [严重] 攻击M2："诚实披露证伪"作为贡献的循环论证

- **攻击点**：R3 把"诚实披露证伪 + 时间线透明"作为 C2 的贡献，但这只是诚实，不是科学贡献
- **攻击逻辑**：
  1. **R3 的 C2 贡献声称**：§4.2 C2 "诚实披露证伪 + post-hoc exploratory observation + 时间线透明"是开放科学贡献
  2. **循环论证**：
     - "诚实披露证伪"是贡献 → 但"证伪"的假设是事后提出的（M1）→ 事后假设不被支持不是"证伪"，是"事后假设失败" → "诚实披露事后假设失败"只是诚实，不是贡献
     - "时间线透明"是贡献 → 但时间线透明只是披露了研究过程的问题，不是研究本身的贡献
  3. **任何研究都可以"诚实披露"自己的问题**：如果"诚实披露"构成贡献，那所有论文都可以通过"诚实披露局限性"获得贡献分——这不成立
  4. **CBM 审稿人视角**："诚实披露是基本要求，不是贡献。你的C2贡献是什么？只是'我们假设了一个东西，结果不支持'？这不是贡献，这是零结果。"

- **证据**：
  - R3 §4.2 C2："诚实披露证伪 + post-hoc exploratory observation + 时间线透明"
  - R3 §8.2 边际贡献：C2 从 R2 的 +4-6% 降至 +2-3%
  - R3 §1：C2 定位为"开放科学贡献"

- **影响评估**：-3-5%（C2贡献强度不足以支撑CBM接收）
- **建议修补**：将C2贡献从"诚实披露证伪"重新定位为"跨方向稳定性分析（1.9× OOD/ID ratio 的 post-hoc exploratory observation）"——稳定性分析本身有科学价值，不依赖"证伪"叙事

### [严重] 攻击M3：EBT-LT经验查表的循环依赖——"部署前查表"需要目标域数据

- **攻击点**：R3 的 EBT-LT 工具声称是"部署前查表工具"，但使用 EBT-LT 需要目标域数据，与"部署前"矛盾
- **攻击逻辑**：
  1. **EBT-LT 的输入**（§4.2 C4）：(1) 训练集 ID 校准性能；(2) 目标域 OOD 估计（源/目标先验距离、logit 分布距离估计）
  2. **循环依赖**：要计算"源/目标先验距离"和"logit 分布距离估计"，用户需要已有目标域数据（至少未标注数据来估计先验，或少量标注数据来估计logit分布）
  3. **与"部署前"矛盾**：如果用户已有目标域数据，那为什么不直接在目标域上校准？EBT-LT 的价值是"部署前查表"，但如果查表需要目标域数据，那"部署前"的意义是什么？
  4. **R2 的 N4 攻击未真正解决**：R2 反方攻击 N4 提到"循环论证未完全解决：要判断可部署性，需要知道是哪 2/6 方向——但用户怎么知道自己的迁移对属于哪 2/6？"。R3 把 TS-DRA 改名为 EBT-LT 并降级为经验查表，但循环依赖问题没有解决——用户仍需要目标域数据才能查表

- **证据**：
  - R3 §4.2 C4 EBT-LT 输入："目标域 OOD 估计（源/目标先验距离、logit 分布距离估计）"
  - R3 §4.2 C4 定位："部署前查表工具"
  - R2 N4 攻击："循环论证未完全解决"

- **影响评估**：-3-5%（EBT-LT 的实用性存疑，C4贡献进一步削弱）
- **建议修补**：
  1. 明确 EBT-LT 的使用场景：用户已有少量未标注目标域数据（用于估计先验距离），但没有标注数据（不能直接校准）
  2. 或者明确 EBT-LT 只需要源域特征（如源域 ECE、源域 accuracy），不需要目标域数据——但这会进一步削弱工具的预测能力
  3. 诚实承认 EBT-LT 的循环依赖局限性

### [严重] 攻击M4：核心贡献聚焦到"阈值化决策"——ECG 4类分类中不常见的场景

- **攻击点**：R3 把核心贡献聚焦到"TS 在阈值化临床决策中的价值"，但 ECG 4类分类的临床决策通常是 argmax，不是阈值化二值决策
- **攻击逻辑**：
  1. **R3 的核心贡献转向**（P1-5 修补）：从"TS改善校准"转向"TS在阈值化临床决策中的价值"
  2. **ECG 4类分类的临床实践**：
     - PTB-XL/Chapman/CPSC 的标准输出是4类诊断（NORM/MI/STTC/CD），通过 argmax 决定
     - 医生看到的是"最可能的诊断"（argmax），不是"P(MI)=0.62, P(STTC)=0.25, ..."
     - 阈值化决策（P(c) > τ）通常用于二分类场景（如 AF 检测：P(AF) > 0.5 vs < 0.5）
  3. **4类分类中的阈值化决策不常见**：在4类分类中，阈值化决策意味着对每个类分别设置阈值（P(c1) > τ1, P(c2) > τ2, ...），但这不是标准临床实践——标准实践是 argmax
  4. **R3 的核心贡献聚焦到不常见场景**：如果阈值化决策在 ECG 4类分类中不常见，那"TS在阈值化临床决策中的价值"这个核心贡献就空了
  5. **N6 攻击的延续**：R2 的 N6 攻击"不确定性感知工作流在ECG实践中真实性存疑"，R3 用"阈值化决策"替代"不确定性感知工作流"，但"阈值化决策"在 ECG 4类分类中同样不常见——这是 N6 攻击的变体

- **证据**：
  - R3 §0 P1-5 修补："核心贡献从'TS改善校准'转向'TS在阈值化临床决策中的价值'"
  - R3 §4.2 C1："核心转向：TS 在阈值化临床决策中的价值"
  - R3 §5.2 Q1 预防性回应："临床价值在于阈值化决策（聚焦，P1-5）"
  - ECG 临床实践：4类分类标准输出是 argmax

- **影响评估**：-4-6%（核心贡献聚焦到不常见场景，C1贡献声称削弱）
- **建议修补**：
  1. 聚焦"Brier reliability"（纯统计指标，不需要临床工作流支撑）作为核心贡献
  2. 或者明确说明阈值化决策的适用场景（如二分类 AF 检测），不声称4类分类中阈值化决策是标准实践
  3. 降低"阈值化决策"的权重，不作为核心贡献

### [严重] 攻击M5：H1阈值降低到几乎必然成立的水平——Cohen's d > 0.2 是"small effect"下界

- **攻击点**：R3 把 H1 阈值从"决策改变率 > 5%"降为"Cohen's d > 0.2, small effect"，但 Cohen's d > 0.2 几乎任何非零效应都满足，成立的 H1 没有临床意义
- **攻击逻辑**：
  1. **Cohen's d > 0.2 的含义**：Cohen's d = 0.2 是"small effect"的下界。这意味着任何 d > 0.2 的效应都满足 H1
  2. **几乎必然成立**：ECE 0.016 的改善，即使对应的 Brier reliability 改善很小，Cohen's d 也可能 > 0.2（取决于样本量和方差）。在样本量足够大时，即使很小的效应也能达到 d > 0.2
  3. **成立的 H1 没有临床意义**：Cohen's d = 0.21 满足 H1，但 0.21 是非常小的效应，可能没有临床意义。审稿人可能质疑"你把阈值降得这么低，H1 当然成立，但这有什么意义？"
  4. **阈值降低的动机**：R3 把 H1 阈值从 >5% 降为 d > 0.2，可能是为了避免 H1 失败（R2 的 N8 攻击）。但降低到"small effect"下界是过度降低——这使 H1 从"有临床意义的假设"变成"几乎必然成立但无临床意义的假设"

- **证据**：
  - R3 §9.2 H1："ECE 0.016 的改善对应可感知的 Brier reliability 改善（Cohen's d > 0.2, small effect）"
  - R3 §0 P1-7 修补："H1从'Cohen's d > 0.5'降为'Cohen's d > 0.2, small effect'"
  - Cohen's d = 0.2 是"small effect"下界（Cohen 1988）

- **影响评估**：-3-5%（H1 几乎必然成立但无临床意义，E3贡献削弱）
- **建议修补**：
  1. 将 H1 阈值设为 Cohen's d > 0.3（small-to-medium effect），而不是 0.2
  2. 或者同时报告效应量大小和临床意义，不依赖单一阈值
  3. 诚实声明：H1 阈值的选择是主观的，不同阈值可能给出不同结论

### [严重] 攻击M6："所有假设都是 exploratory"声明削弱统计推断价值

- **攻击点**：R3 声明"All hypotheses tested in this paper should be considered exploratory, not confirmatory pre-registered hypotheses."但如果所有假设都是 exploratory，那论文的统计推断（p值、CI）有什么意义？

- **证据**：

  - R3 §4.2 C2：1.9× 标记为"post-hoc exploratory observation"

- **影响评估**：-4-6%（如果审稿人认为论文只是探索性分析，可能降低接收概率或要求major revision）

  2. 或者明确说明：虽然所有假设都是 exploratory，但实验设计（数据集选择、评估指标、统计方法）是预先确定的，只有假设检验的确认性级别是 exploratory

### [严重] 攻击M7：NCV定义不对称——系统性低估TS的临床价值

- **攻击点**：R3 的 NCV 定义考虑了 false class 的改错（FP_worsened），但未考虑 false class 的改对（从"报告错误类"到"不报告错误类"也是改对），导致 NCV 系统性低估 TS 的临床价值
- **攻击逻辑**：
  1. **R3 的 NCV 定义**（§3.2 E3）：
     - TP_improved：对 true class c，TS 后决策更接近真实标签（从 p_c ≤ τ 到 p_c > τ，且 c 是真实标签）→ 改对
     - FP_worsened：对 false class c'，TS 后决策更远离真实标签（从 p_c' ≤ τ 到 p_c' > τ，且 c' 不是真实标签）→ 改错
  2. **不对称问题**：R3 考虑了 false class 的改错（FP_worsened），但未考虑 false class 的改对：
     - 对 false class c'，TS 前预测 p_c' > τ 但 TS 后 p_c' ≤ τ（从"报告错误类 c'"到"不报告错误类 c'"，且 c' 不是真实标签）→ **这也是改对！**
  3. **系统性低估**：TS 是全局单一温度，对所有类的置信度同时缩放。如果 T>1（降温），所有类的置信度向 1/K 靠拢：
     - 对 true class：可能从 p_c > τ 变为 p_c ≤ τ（改错）
     - 对 false class：可能从 p_c' > τ 变为 p_c' ≤ τ（改对！）
  4. **R3 的 NCV 忽略了 false class 的改对**：如果 TS 降温导致 false class 的误报减少（改对），R3 的 NCV 不计入这部分改对，导致 NCV 系统性低估 TS 的临床价值

- **证据**：
  - R3 §3.2 E3 NCV 定义："TP_improved：对 true class c... FP_worsened：对 false class c'..."
  - 定义中只有 true class 的改对和 false class 的改错，没有 false class 的改对

- **影响评估**：-2-3%（NCV定义不对称，可能系统性低估TS价值，但这也意味着R3的NCV是保守估计）
- **建议修补**：
  1. 扩展 NCV 定义：NCV = (TP_improved + TN_improved - FP_worsened - FN_worsened) / N_total
     - TN_improved：对 false class c'，从 p_c' > τ 到 p_c' ≤ τ（改对）
     - FN_worsened：对 true class c，从 p_c > τ 到 p_c ≤ τ（改错）
  2. 或者明确说明：当前 NCV 是保守估计（只考虑 true class 的改对），完整 NCV 可能更高

## 是否需要R4轮的判断

### 判断：**需要R4轮**

### 理由

1. **R3 修补了 R2 的致命攻击 N1**：R3 真正放弃了预注册叙事，规避了学术不端风险。这是 R3 的重大改进。

2. **但 R3 引入了9个新的严重攻击**（M1-M9）：
   - M1（证伪语义陷阱）和 M2（诚实披露不是贡献）削弱了 C2 贡献
   - M3（EBT-LT循环依赖）削弱了 C4 贡献
   - M4（核心贡献聚焦到不常见场景）和 M8（备选叙事矛盾）削弱了 C1 贡献
   - M5（H1阈值过低）和 M6（所有假设exploratory）削弱了 E3 贡献
   - M7（NCV定义不对称）和 M9（假设分层cherry-picking）是方法论问题

3. **最严重的新问题是 M4+M8 的组合**：无论 H1 是否成立，R3 的核心贡献都聚焦到 ECG 实践中不常见的场景（阈值化决策或不确定性感知工作流）。这可能是审稿人质疑论文根本贡献的依据。

4. **M6 可能导致 major revision**：如果审稿人认为"所有假设都是 exploratory"使论文不构成 confirmatory 贡献，可能要求 major revision 而非直接接收。

### R4轮修补优先级

**P0（必须）**：
- 重新定位核心贡献：从"阈值化决策"转向"Brier reliability 改善作为纯统计贡献"（解决 M4+M8）
- 区分 exploratory 和 confirmatory 部分（解决 M6）

**P1（重要）**：
- 修正"证伪"叙事：改为"post-hoc hypothesis not supported by data"（解决 M1）
- 重新定位 C2 贡献：从"诚实披露证伪"转向"跨方向稳定性分析"（解决 M2）
- 解决 EBT-LT 循环依赖：明确使用场景或只需源域特征（解决 M3）
- 提高 H1 阈值至 d > 0.3 或同时报告效应量大小和临床意义（解决 M5）
- 扩展 NCV 定义：加入 false class 的改对（解决 M7）
- 诚实声明假设分层的 cherry-picking 风险（解决 M9）

**P2（轻微）**：
- 修正接收概率估计的表述（M10、M12、M15）
- 延长时间表至10-12周（M11）
- 独立核实 Table X 数据（M13）
- 将 C3 贡献改为"分箱温度的探索性评估"（M14）
