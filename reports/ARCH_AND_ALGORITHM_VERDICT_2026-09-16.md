# 加架构 + 算法创新：可行性裁决报告

**日期**：2026-09-16
**用户目标**：① 增加架构 ② 最好研究出新的算法
**方法**：BiMamba 显存根因实测 + 分块扫描等价性验证 + 2 路对抗子代理（algo-hunter 提案 / algo-critic 证伪）+ 主代理对全部数字独立复算
**结论**：② **不成立**（三条候选算法路线全部否决）；① **成立且是当前最高价值投入**，但必须先在统一口径下重跑。

---

## 0. 一句话结论

**"加算法"这个方向本轮被证伪了，但证伪过程挖出了一个比算法更值钱的东西 —— 论文 cross-fit 一节的口径混乱。** 先修它、再加架构，才是正确顺序。硬上算法会把一个"口径混乱"升级成"结论错误"。

---

## 1. BiMamba OOM 根因：可修，但**不是**论文贡献

### 1.1 根因定位（实测）

`mambapy` 的 `selective_scan` 在 pscan 模式下物化 `(B, L, ED, N)` 中间张量并保留全时间步历史：

```python
deltaA = torch.exp(delta.unsqueeze(-1) * A)   # (B, L, ED, N)
deltaB = delta.unsqueeze(-1) * B.unsqueeze(2) # (B, L, ED, N)
BX = deltaB * (x.unsqueeze(-1))               # (B, L, ED, N)
hs = pscan(deltaA, BX)
```

`d_model=64, expand=2 → ED=128`，`d_state=16 → N=16`。`B×L=80000` 时单个张量 ≈ 0.65 GB，pscan 内部保留多份 → 单层 >8 GB。

### 1.2 显存代价实测（RTX 5060 Laptop, 8.5 GB）

| 配置 | 峰值显存 | 耗时 |
|---|---|---|
| 原实现 pscan, B=16, L=2500 | 4.50 GB | 1.22 s |
| **chunk=500 分块** | **1.98 GB** | **0.12 s** |
| checkpoint + chunk=500 | **0.74 GB** | 0.16 s |
| sequential (pscan=False) | 2.58 GB | 18.93 s |
| 4 层完整骨干（原实现） | 17.00 GB → OOM | — |

**关键发现**：B=16 时原实现**已能跑通**（4.50 GB）。论文 OOM 说明当时用的是 B=32（实测 33.96 GB）。**分块后 B=32 也有希望**。

### 1.3 但分块不是数学恒等（重要，勿当创新点包装）

实测分块与全序列的偏差：

| 策略 | chunk=1000 | chunk=500 | chunk=250 |
|---|---|---|---|
| 朴素分块 max\|Δ\| | 7.98e-2 | 1.13e-1 | 1.13e-1 |
| 左侧补 conv 上下文 max\|Δ\| | 1.75e-3 | 3.47e-3 | 3.47e-3 |

**偏差来源有两处**：
1. depthwise `conv1d`（d_conv=4）跨越块边界 → 补左侧 3 个 token 可把偏差从 1.1e-1 压到 3.5e-3
2. **SSM 递归状态 h 跨块累积** → 实测 SSM 分块 mean\|Δ\| 2.24e-4，必须显式传递状态 h (B, ED, N)

`mambapy` 公共 API 未暴露状态传递接口，因此**严格恒等分块需要自己重写 selective_scan**。

### 1.4 结论

- BiMamba **可以作为第 3 个架构跑真格**（用分块 + 小 batch），**不需要把它写成算法贡献**。
- 若包装成"chunked linear-time SSM"，会被审稿人指出这是已知工程技巧（Mamba 官方实现本就有 chunked scan），**不是新算法**。

## 2. 算法创新三条路线：全部否决

### 2.1 路线 1（algo-hunter 最推荐）—— 否决

**提案**：用无标签 shift 统计量替代 (s, b, π) 分解，报告 RMSE 0.1176 → 0.0769（−34.6%）。

**证伪（algo-critic 实测 + 主代理复核）**：

- algo-hunter 的目标变量用错了。它用的 `delta_obs`（均值 **+0.1068**）**不是**论文主终点。论文主终点对应的是 `delta_obs_orig`（均值 **+0.0159**，与论文逐位吻合）。
- **T 分层铁证**：

| T 区间 | n | `delta_obs` | `delta_obs_orig` |
|---|---|---|---|
| [0.0, 1.5) | 27 | +0.0294 | +0.0165 |
| [1.5, 2.0) | 3 | +0.0875 | +0.0221 |
| [2.0, 3.0) | 17 | +0.1385 | +0.0114 |
| [3.0, 5.0) | 13 | **+0.2308** | +0.0191 |

`delta_obs` 随 T 单调膨胀，**直插噪声底区间**（T≥3 时底噪 0.095–0.136，实测 0.2308）→ 它是 **SmoothECE 噪声伪信号**。`delta_obs_orig` 在 T 上**平坦** → 真实 T-不变效应。

- 在正确口径下：RMSE 常数 **0.0145** → 特征集 **0.0121**，改善仅 **16.7%**，且**方向准确率 0.833 反而低于常数 0.850**。
- algo-hunter 引用的三个相关系数**全部反号**：`corr(ΔECE, ood_acc)` 由 −0.814 → **+0.127**；`corr(ΔECE, T)` 由 +0.688 → **+0.103**。

**判定**：方向 1 是在拟合噪声伪信号。**做下去会把"口径混乱"升级为"结论错误"。最不该做。**

### 2.2 路线 2（King-Zeng 协变量偏移失效界）—— 否决

"King-Zeng 失效界 + 协变量偏移"是 2018 年以来的标准工具箱（Ben-David 界、GLS、importance weighting）。要做成真新意需要：① 证明多类 top-label ECE 的界在 label shift 下紧；② 给出可估的界并证明比常数基线紧。

但数据已显示 **ΔECE 与所有无标签量相关 |r| < 0.21** → 界大概率松到无意义。理论工作量 ≥1 篇独立论文，且风险是证出"不可预测"这个论文已有的结论。**新意中低。**

### 2.3 路线 3（BBSE 接进 `prev_hat`）—— 否决

设计常量回读的误差是 **0.0**（合成数据重采样确实精确控制了正类数），接入 BBSE 后跳到 **0.12–0.20**。这是**负收益换皮**。且先验估计不改善 top-label ECE，**与主终点无关**。

## 3. 本轮真正挖出的硬伤：cross-fit 一节口径混乱

**这比任何算法创新都紧急。**

### 3.1 论文的 "+0.29" 是对的（algo-hunter 在此判错）

用正确字段（`delta_obs_orig`）复算：

| 量 | 实测 | 论文声称 |
|---|---|---|
| 预测误差 mean | **+0.2856** | +0.29 ✅ |
| 预测误差 median | **+0.2913** | +0.29 ✅ |

论文无误。algo-hunter 报的 +0.1906 是减了错字段。

### 3.2 但 "85% 方向准确率" 确实零信息量

```
delta_obs_orig > 0        : 51/60 = 85.0%
常数预测器（恒输出"正"）  : 51/60 = 85.0%   ← 逐位相等
分解模型方向准确率        : 51/60 = 85.0%
```

**三者完全相等。** 该指标无信息量，必须改报 Cohen's κ 或相对常数基线的增量。

### 3.3 最致命的一条：分解模型 RMSE 比常数差 21 倍

| 模型 | RMSE |
|---|---|
| 常数（预测 obs 均值） | **0.0145** |
| 分解模型 | **0.3029** |

**0.3029 / 0.0145 = 20.86 倍。** 论文的"predictability boundary"结论方向是对的（甚至该更强调），但**引用的支撑数字口径混乱**，审稿人一核对就会发现端点与诊断用了两套 ECE。

### 3.4 另有两处描述不可复现

- **错误簇**：论文称 9 个方向错误聚集在 CPSC→Chapman 与 Chapman→PTB-XL；实测分布为 `chapman→cpsc: 2, chapman→ptbxl: 2, cpsc→chapman: 2, cpsc→ptbxl: 2, ptbxl→chapman: 1`（5 个方向都有，无集中簇）。
- **Wasserstein**：论文称 0.75 vs 0.53；实测全体均值 **0.569**。

### 3.5 生成脚本丢失（provenance 缺陷）

全仓 grep `delta_pred`，**除 review 代理自己的临时脚本外无任何 `.py` 来源**。`results/strengthening_battle_corrected.json` 无法从仓库内复现。**这是 reproducibility 层面的硬伤，必须先重建脚本。**

### 3.6 定级：**致命级**（非笔误级）

三条叠加越线：① 主终点与诊断端点用两套 ECE 口径，量级差 7 倍；② 85% 方向准确率精确等于常数基线却被当作支撑证据；③ 生成脚本丢失。

**但有一个重要的自证机制**：`delta_obs_orig` 的 **T-不变性**（+0.0165/+0.0221/+0.0114/+0.0191）实际上**支持主终点 +0.0159 是真实的**。这与本报告第一轮独立做的噪声底机理检验（斜率 β̂=+0.00155，比机理值小 29 倍）**互为独立佐证**。问题是论文现在的写法无法自证这一点。

| 优先级 | 动作 | 成本 | 收益 |
|---|---|---|---|
| **P0** | **统一口径**：全仓只保留 `delta_obs_orig`（raw − post），`delta_obs` 明确标注为噪声诊断量 | 低 | 所有后续工作的前提 |
| **P0** | **重建 cross-fit 生成脚本**（当前 JSON 无 provenance） | 中 | 可复现性硬伤 |
| **P0** | **把"分解模型 RMSE 0.3029 劣于常数 0.0145（21 倍）"写成正面结果** | 低 | 强化已有 predictability boundary 叙事，从"被审稿人打"变成"自己先打死" |
| **P0** | 修正两处不可复现描述（错误簇分布、Wasserstein 0.569） | 低 | 内部一致性 |
| **P1** | **加第 3 个架构 BiMamba**（用分块扫描 + B=16~32 跑真格） | 中 | 删掉"仅 2 种架构"这条 Limitations |
| **P1** | 85% 方向准确率改报 Cohen's κ + 常数基线对照 | 低 | 消除零信息量指标 |
| P2 | 若仍要第 4 个架构：`inceptiontime_lite` 已有实现但实验为空（`results/c3_inceptiontime_lite_30exp.csv` 只有表头，0 训练 0 迁移），可低成本补跑 | 低 | 架构家族多样性 |

**明确不做**：
- ❌ 路线 1（无标签特征替代分解）—— 噪声拟合
- ❌ 路线 2（King-Zeng 失效界）—— 教科书换皮，除非愿写独立理论论文
- ❌ 路线 3（BBSE 接 prev_hat）—— 负收益换皮
- ❌ 把"分块 Mamba"包装成新算法 —— 已知工程技巧

## 6. 诚实底线

- **本轮没有产生任何可发表的新算法。** 三条候选全部否决，否决理由均已实测。
- **"加架构"是真实可行的**，且 BiMamba 的 OOM 已被证明是可修的工程问题，不是硬件天花板。
- **但顺序不能反**：先在统一口径下重跑，再加架构。否则新架构的 ΔECE 会再次落进口径混乱里。
- 论文 cross-fit 一节的问题**不是造假**，是口径混乱 + provenance 缺失。但它是**致命级**的内部一致性缺陷，CMPB 的统计方法学审稿人跑一次常数基线就会命中。
